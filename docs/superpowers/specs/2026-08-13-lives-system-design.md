# 《校园寻宝》命数系统设计

日期：2026-08-13
状态：已实现

## 1. 目标

在现有“找到宝箱 → 答题 → 刷新下一宝箱”的无限循环之上，加入单局命数与终局机制：每位玩家初始 3 条命，答错扣 1 条命并继续寻找下一个宝箱；任何一次答对即视为本局胜利并结束。结束游戏的两种情况：

1. 找到宝箱并答对 → 胜利。
2. 三条命全部扣完 → 失败。

游戏结束后显示覆盖层，自动重开回到标题画面，下一位玩家按 WASD 或方向键开始新的一局。

## 2. 核心规则

- 每位玩家初始 3 条命（`GameConfig.STARTING_LIVES := 3`）。
- 找到宝箱后答题规则保持不变：4 个选项恰 1 个正确，仅鼠标点击，每题仅 1 次机会，首次有效点击后立即结算。
- 答对：进入现有 4 秒庆祝流程（“回答正确，请领取奖品”），庆祝结束后**本局胜利结束**，不再刷新下一宝箱。
- 答错：首次有效点击后立即扣 1 条命并更新心形，仍显示现有 2 秒“挑战失败，本轮无奖”反馈。反馈结束后：
  - 若仍有剩余命（`lives > 0`），刷新下一宝箱并回到 `SEARCHING` 继续寻宝。
  - 若命数已耗尽（`lives <= 0`），进入失败终局，不再刷新宝箱。
- 胜利与失败均不改变玩家位置。
- 失败终局显示失败覆盖层，等待固定时长后自动重开；重开复位命数为 3、题号为 0、玩家回起点、生成首个宝箱，并回到 `WAITING_START` 标题画面。
- 重开后下一位玩家按首次移动键开始新的一局，沿用现有开始流程。
- 胜利路径不新增单独的胜利覆盖层：4 秒庆祝覆盖层本身即胜利画面，庆祝结束直接进入自动重开（失败侧的覆盖层 + 计时器与胜利侧对称，但胜利侧不额外加覆盖层，以缩短换人时长）。

## 3. 状态与数据流

`GameFlow` 在现有 `WAITING_START`、`SEARCHING`、`QUIZZING`、`CELEBRATING` 之上新增两个终态：`WON`、`GAME_OVER`。完整状态流为：

1. `WAITING_START`：等待玩家首次移动输入。
2. `SEARCHING`：角色可移动，导航指向当前宝箱。
3. `QUIZZING`：玩家触碰宝箱后进入；角色停止移动，导航隐藏，宝箱停止碰撞检测，答题面板出现。
4. 答对 → `CELEBRATING`；4 秒庆祝结束 → `WON`（胜利终局），不再回到 `SEARCHING`。
5. 答错 → 留在 `QUIZZING` 显示 2 秒失败反馈；反馈结束后：
   - 仍有命 → `SEARCHING`，刷新下一宝箱。
   - 命数耗尽 → `GAME_OVER`（失败终局），不再刷新宝箱。
6. `WON` 或 `GAME_OVER` → 重开计时器到点 → `WAITING_START`。

旧宝箱在进入答题状态时保留但停止检测，避免答题时重复触发。答对路径在庆祝期间仍保留旧宝箱，庆祝结束后直接进入终局，不刷新新宝箱；答错且仍有命时，`TreasureSpawner` 在失败反馈结束后替换旧宝箱。`GameFlow.on_round_finished()` 收紧为只允许 `QUIZZING → SEARCHING`（答错续关路径），`CELEBRATING` 不再经由 `on_round_finished()` 回到 `SEARCHING`。

## 4. 模块职责

- `src/config/game_config.gd`：新增 `STARTING_LIVES := 3` 常量。
- `src/core/game_flow.gd`：管理 `WAITING_START`、`SEARCHING`、`QUIZZING`、`CELEBRATING`、`WON`、`GAME_OVER` 状态与合法转换；新增 `on_win()`、`on_game_over()`、`reset_to_start()` 及对应信号；`on_round_finished()` 仅接受 `QUIZZING → SEARCHING`。
- `src/ui/game_ui.gd` 与 `src/ui/game_ui.tscn`：在现有覆盖层之上新增失败覆盖层 `GameOverOverlay` 与重开计时器 `RestartTimer`；新增左上角心形命数指示，由 `set_lives(n)` 驱动满心/空心；发出 `restart_requested` 信号。现有答题、庆祝、失败反馈、致命错误流程保持不变。
- `src/main/main.gd`：维护 `lives`，串联宝箱、题库、状态机、玩家、导航、UI 与心形；答对路径在庆祝结束后进入 `WON` 并启动重开；答错路径扣命并据剩余命分流为续关或失败终局；重开复位一切并回到标题。
- `tools/generate_art.gd` 与 `tools/validate_art.gd`：把 `ui.png` 由 64×32 扩展为 96×32，新增两个 16×16 心形区域（满心、空心），用现有调色板色；同步更新校验契约。
- `README.md`、`docs/qa/manual-test-checklist.md`、`CLAUDE.md`：同步描述命数、胜负、重开与心形；把“不显示计数器”约束改为“命数心形除外”，并保留各自被测试断言的关键字样。

## 5. UI 设计

### 失败覆盖层

`GameOverOverlay` 复用现有深蓝底、金色边框与内置中文字体，居中显示，文案为“挑战失败，命数耗尽”。与现有覆盖层互斥：显示失败覆盖层时隐藏其他所有覆盖层。失败覆盖层出现时同时启动 `RestartTimer`（one_shot，固定时长），到点发出 `restart_requested` 信号；失焦暂停策略覆盖该计时器。

### 心形命数指示

左上角常驻 3 个固定槽位的心形指示，仅使用调色板内颜色（满心为秋叶橙填充 + 深棕轮廓，空心为深棕轮廓 + 透明）。`set_lives(n)` 将第 `i` 个槽位设为满心（`i < n`）或空心（`i >= n`）。指示在 `WAITING_START` 标题画面与终局覆盖层显示期间隐藏，在 `SEARCHING`、`QUIZZING`、`CELEBRATING` 期间可见。

### 庆祝作为胜利画面

胜利路径沿用现有 4 秒庆祝覆盖层（“回答正确，请领取奖品”与金色粒子），不新增胜利覆盖层。庆祝结束后由主控进入 `WON` 并直接启动自动重开。

## 6. 异常与边界处理

- 题库为空或题目结构非法时仍显示现有致命错误覆盖层，不进入游戏循环，命数机制不参与。
- 选项索引越界、重复点击禁用选项或结算后再次点击均不产生状态变化，亦不扣命、不推进终局。
- 重开后的首个宝箱生成失败时沿用现有致命错误处理，角色保持锁定且导航隐藏。
- 应用失焦时沿用现有暂停策略，失败反馈计时、庆祝计时与重开计时器一并暂停。
- 命数为 0 时的答错不得刷新下一宝箱；胜利路径不得刷新下一宝箱。两条终局路径都只复位一次到标题。
- 重开是确定性复位：命数、题号、玩家位置、宝箱、导航、心形、覆盖层全部回到首局初始状态。

## 7. 验收与测试

自动测试必须覆盖：

- `GameFlow` 新增 `WON`、`GAME_OVER` 状态及 `on_win()`、`on_game_over()`、`reset_to_start()` 转换的合法性与非法前置态拦截；`on_round_finished()` 仅接受 `QUIZZING → SEARCHING`，拒绝 `CELEBRATING`。
- 答对路径：找到宝箱 → 答对 → `CELEBRATING` → 4 秒庆祝结束 → `WON`，期间不刷新下一宝箱、不扣命、玩家位置不变。
- 答错续关路径：答错扣 1 命，2 秒反馈结束后若仍有命则回到 `SEARCHING` 且只刷新一个新宝箱，玩家位置不变，心形随之更新。
- 失败终局路径：连续 3 次答错后命数为 0，进入 `GAME_OVER`，显示失败覆盖层，不刷新下一宝箱；重开计时器到点后回到 `WAITING_START` 并复位命数=3、题号=0、玩家回起点、生成首个宝箱。
- 心形指示：初始 3 满心，每次答错减少一颗满心，终局/标题期间隐藏，重开后恢复 3 满心。
- 重开后下一位玩家按移动键可正常开始新的一局，且新一轮的第 1 题使用题库第 1 题。
- 重开计时器受失焦暂停策略覆盖。
- 现有答题仅鼠标、单次机会、不重复结算、不传送等不变量继续通过。
- 原有导航、玩家、场景、暂停、美术校验测试继续通过（美术契约更新后 `validate_art.gd` 通过）。

人工验收必须检查：

- 640×360 逻辑画布及 1280×720 显示下，失败覆盖层与心形指示完整可读、不与现有答题/庆祝面板重叠。
- 左上角心形随答错逐颗变空，且在标题与终局期间不可见。
- 答对后 4 秒庆祝随即自动重开回到标题；答错至第 3 次显示失败覆盖层后自动重开回到标题。
- 失败覆盖层期间切换窗口，确认重开计时器与失败反馈计时器一同暂停。
- 完整走通一次胜利路径与一次失败路径，确认两种路径都保持玩家原地不传送。

## 8. 不做

- 不做单独的胜利覆盖层：4 秒庆祝即为胜利画面。
- 不做命数之外的任何计数器、排行榜或得分。
- 不做手动重开按键：重开仅由终局覆盖层后的自动计时器触发；标题画面仍由首次移动键开始。
- 不做存档：重开即复位，跨局不保留任何进度。
- 不做音频、网络、品牌内容、多地图、背包、NPC 等（沿用既有“不做”清单）。
