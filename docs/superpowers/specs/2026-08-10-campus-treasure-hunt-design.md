# 《校园寻宝》游戏设计文档

日期：2026-08-10  
状态：已批准  
目标平台：Windows x64 电脑、键盘操作  
技术方案：Godot 4，Compatibility 渲染器

## 1. 项目概述

《校园寻宝》是一款为高中科技节展会制作的单机像素风寻宝游戏。玩家控制一名学生在暖秋校园地图中寻找宝箱。宝箱在游戏内不提供能力、货币或收集进度，只对应线下活动的奖品兑换。

游戏面向现场轮流体验，目标单轮时长为 2–3 分钟。找到宝箱后，角色留在原地，新宝箱在地图另一处生成，游戏立即进入下一轮。身份识别、兑奖核验、排队和每人参与次数由现场工作人员线下管理。

## 2. 目标与验收结果

- 玩家无需讲解即可凭屏幕提示开始移动和寻找。
- 首次体验者中至少 90% 能在 3 分钟内找到宝箱。
- 每次找到宝箱后，下一轮无需重载场景即可自动开始。
- 连续运行和刷新 500 次宝箱时，不出现不可达宝箱、流程卡死或角色被传送。
- 在常见 Windows 集成显卡电脑上以 1280×720 稳定达到 60 FPS。
- 成品可通过单个 Windows x64 `.exe` 双击启动并全屏运行。

## 3. 明确不做的内容

- 不适配手机、平板、手柄、macOS 或 Linux。
- 不制作 NPC、对话、任务、谜题、背包、装备、经济、成就、排行榜或存档。
- 不加入科学问答、科技节展品或教育内容。
- 不接入账号、服务器、数据库、统计、兑奖码或二维码。
- 不验证重复兑奖，也不区分当前操作者身份。
- 不加入学校名称、校徽、科技节名称或其他定制品牌元素。
- 不制作或播放背景音乐与音效。
- 不进入建筑内部，不制作多地图或场景切换。

## 4. 核心玩法

### 4.1 输入

- `WASD` 和方向键均可控制角色移动。
- 不需要鼠标或互动键。
- 角色接触宝箱后自动判定找到。
- 只有移动输入能推进玩家流程，避免现场参与者需要记忆额外按键。

### 4.2 首次启动

1. 游戏全屏启动，显示标题《校园寻宝》和“按方向键开始”。
2. 角色位于校园中央广场，首个宝箱已在合法候选点生成。
3. 玩家首次按下移动键后，标题提示淡出并进入寻找状态。

### 4.3 寻找过程

1. 跟随镜头以像素对齐方式平滑跟随角色，并限制在地图边界内。
2. 右上角罗盘箭头持续精确指向宝箱，而非八方向分档。
3. 罗盘旁显示玩家到宝箱的欧氏直线距离，格式为“距离宝藏 N 米”。
4. 距离采用 `16 像素 = 1 米` 的固定比例并四舍五入为整数。
5. 宝箱进入镜头范围后直接可见；角色接触宝箱后自动触发成功。

### 4.4 找到宝箱与连续接力

1. 游戏进入约 4 秒的庆祝状态，暂时锁定角色移动。
2. 屏幕显示像素庆祝效果和“找到宝藏！请领取奖品”。
3. 当前宝箱消失，角色位置保持不变。
4. 系统选择新的合法宝箱点并更新罗盘目标。
5. 庆祝结束后自动解锁移动，下一轮就地开始；不返回中央广场，不显示新的开始页，也不重载地图。

游戏没有失败、生命值、倒计时或游戏结束状态。当前玩家可以继续，也可以由下一位玩家从当前位置接手。

## 5. 宝箱生成规则

地图包含约 40 个由人工放置并验证的候选点。采用候选点池而非任意坐标随机，以保证所有位置可到达、可碰撞且不会落入装饰物或地图边界之外。

每次生成必须满足：

- 候选点不是上一只宝箱所在点。
- 候选点与玩家的直线距离至少为 18 米。
- 候选点处于玩家可以步行到达的区域。
- 候选点周围留有足够碰撞空间，角色能够接触宝箱。

系统从全部合格点中等概率随机选择。如果没有候选点满足最低距离，则选择除上一点之外、距玩家最远的合法点。地图制作完成后通过自动测试验证全部候选点的可达性与碰撞空间。

## 6. 地图设计

### 6.1 空间结构

- 单张连续的自然校园户外地图，初始目标尺寸为 96×72 个 16 像素图块。
- 地图大于单屏，通过跟随镜头浏览，约为一个视口的 2–4 倍面积。
- 斜向道路、湖岸和错落建筑形成自然布局，同时保留清晰的主路循环。
- 建筑、树木、围栏和水面构成碰撞与绕行，但不制作狭窄、难以辨认的迷宫通道。

### 6.2 主要地标

- 中央广场：首次启动出生点和全图视觉中心。
- 教学楼：砖红屋顶与浅色墙面的大型地标。
- 湖边：水面、岸线、木桥或长椅形成明显边界。
- 花园：花坛、灌木与较密集的秋季色彩。
- 林荫道：连接主要区域的主循环道路。
- 侧门：地图边缘的方向性地标。

地标应在颜色、轮廓和周边装饰上相互区分，帮助玩家理解自身位置。宝箱点分布在地标周围、道路转角和可进入的小型开放空间，不放在视觉不可读的死角。

## 7. 美术设计

### 7.1 总体方向

采用原创的暖秋校园像素风。视觉气质参考田园生活类像素游戏的温暖、清晰和亲切感，但不复刻《星露谷物语》或其他作品的角色、建筑、图块、配色组合与动画。

主色关系：

- 草地：中等明度的暖绿色。
- 道路：米黄、浅土色。
- 建筑：砖红屋顶、奶油色墙面。
- 植被：橙色、金黄、红褐和少量深绿。
- 水面：低饱和蓝绿色。
- 轮廓与阴影：深棕灰，避免纯黑形成过硬边缘。
- 导航强调色：金黄色，与宝箱保持一致。

### 7.2 素材规格

- 地图图块基础网格：16×16 像素。
- 玩家角色约 24×32 像素，包含上、下、左、右四方向待机与行走动画。
- 宝箱包含待机微光、开启和消失动画。
- 水面、树叶与花草使用低频环境动画，避免画面过度闪烁。
- 庆祝效果使用星形粒子、金色闪光和短促的屏幕强调动画。
- 所有正式游戏素材均为本项目原创 PNG 图集，并保留源文件与色板说明。

### 7.3 显示规格

- 基准逻辑画布为 640×360，16:9。
- 采用整数倍像素缩放，优先覆盖 1280×720 和 1920×1080。
- 1366×768 等不能整数铺满的分辨率保持画面比例并使用黑边，不拉伸像素。
- 默认全屏启动，使用 Godot Compatibility 渲染器以兼容常见集成显卡。

## 8. 界面设计

### 8.1 探索界面

- 右上角为唯一常驻 HUD。
- HUD 包含圆形罗盘、精确旋转箭头和“距离宝藏 N 米”。
- HUD 使用深色半透明底板、浅色边框和金色强调，保证在草地、道路、水面上均可读。
- 首次开始后的底部操作提示“WASD / 方向键移动”在数秒后淡出。

### 8.2 庆祝界面

- 屏幕中心显示“找到宝藏！请领取奖品”。
- 金色像素粒子从宝箱位置向外扩散，画面可有轻微停顿或缩放强调。
- 庆祝总时长约 4 秒，结束后 HUD 自动指向新宝箱。
- 不显示兑奖码、二维码、累计数量或玩家姓名。

### 8.3 文字与声音

- 中文字体随游戏打包，确保不依赖系统已安装字体；选用许可允许再分发、在小尺寸下清晰的字体。
- 全程无背景音乐和音效，工程中不加载音频总线或音频资源。

## 9. 技术架构

### 9.1 场景与职责

- `Main`：组合世界、玩家、镜头、宝箱系统和界面。
- `GameFlow`：管理 `WAITING_START`、`SEARCHING`、`CELEBRATING` 三种状态以及状态转换。
- `Player`：读取键盘输入，执行速度归一化、移动、碰撞和四方向动画。
- `World`：保存 TileMap 图层、Y 排序对象、碰撞层和宝箱候选点。
- `TreasureSpawner`：筛选候选点、执行随机选择、提供最远点回退并实例化宝箱。
- `Treasure`：检测玩家接触并发出 `found` 信号。
- `NavigationHUD`：根据玩家与当前宝箱的位置差更新箭头旋转和距离文本。
- `CelebrationUI`：显示成功覆盖层与粒子动画，并在动画结束时发出完成信号。
- `Camera2D`：跟随玩家并受地图矩形边界约束。

每个模块只通过明确的信号或公开方法协作，避免界面、生成逻辑和玩家控制相互直接修改内部状态。

### 9.2 状态与数据流

1. `GameFlow` 启动后进入 `WAITING_START`，生成首个宝箱并锁定角色移动。
2. 玩家按移动键后进入 `SEARCHING` 并解锁角色。
3. `NavigationHUD` 每帧读取玩家和宝箱全局坐标，更新箭头与距离。
4. `Treasure` 检测到玩家后发出 `found`。
5. `GameFlow` 进入 `CELEBRATING`，锁定移动并启动庆祝界面。
6. 庆祝期间 `TreasureSpawner` 删除旧宝箱并选择新目标。
7. 庆祝结束后 `GameFlow` 回到 `SEARCHING`，解锁角色，HUD 已指向新目标。

## 10. 异常与现场恢复

- 启动时验证至少存在两个宝箱候选点；验证失败时显示明确的中文错误页，不进入游戏。
- 随机筛选没有合格点时回退到距玩家最远的合法点，保证流程继续。
- 窗口失去焦点时暂停移动与庆祝计时，恢复焦点后继续。
- 地图边界使用完整碰撞与镜头限制，角色不能离开可玩区域。
- 游戏不访问网络；网络不可用不会影响启动或玩法。
- 现场异常时，工作人员关闭并重新启动 `.exe` 即可恢复到中央广场和首轮状态。游戏没有需要恢复的持久数据。

## 11. 测试方案

### 11.1 自动化测试

- 验证宝箱不会连续生成在同一点。
- 验证正常情况下宝箱与玩家距离不小于 18 米。
- 验证无合格点时选择最远合法点。
- 验证全部候选点位于可玩区域并具有接触空间。
- 使用已知坐标验证箭头角度、直线距离和整数米数显示。
- 验证 `WAITING_START → SEARCHING → CELEBRATING → SEARCHING` 状态转换。
- 验证庆祝期间移动锁定、庆祝结束后原地解锁。
- 连续模拟至少 500 次宝箱刷新，验证不会返回空目标或卡死。

### 11.2 人工验收

- 在 1280×720、1366×768 和 1920×1080 分辨率下检查全屏、黑边和像素缩放。
- 检查 `WASD`、方向键、长按、同时按键、撞墙和地图边界行为。
- 连续完成至少 20 轮，确认角色位置保留、宝箱刷新和 HUD 更新正确。
- 邀请未看过说明的体验者试玩，记录从首次移动到找到宝箱的用时；至少 90% 在 3 分钟内完成。
- 在常见 Windows 集成显卡电脑上确认 1280×720 稳定 60 FPS。
- 确认整个流程无音频输出、无网络请求、无品牌内容和兑奖验证界面。

若试玩时间偏离目标，只允许调整地图阻挡、候选点分布、角色移动速度和 18 米最低生成距离，不扩大玩法范围。

## 12. 最终交付

- 单文件 Windows x64 `.exe`，资源嵌入程序，可双击全屏启动。
- 完整 Godot 4 工程、源码、测试和导出配置。
- 原创像素素材源文件、PNG 图集与色板说明。
- `README` 现场操作说明，包含启动、退出、重启和常见故障处理。
- 本设计文档以及后续实现计划。

## 13. 实现边界

本规格可由一个实现计划完成。实现顺序应先建立可测试的核心循环与生成逻辑，再完成地图和美术替换，最后进行 Windows 导出与现场试玩调优。任何新增系统均需先修改并重新批准本设计文档。
